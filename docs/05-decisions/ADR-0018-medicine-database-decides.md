# ADR-0018: The medicine database decides; the model only explains

**Context.** Indian prescriptions name brands. One molecule reaches a patient through several products from several prescribers (Atorva 10 from the cardiologist, Ecosprin-AV from the GP), and fixed-dose combinations hide molecules (Combiflam = ibuprofen + paracetamol). A caregiver asking "can papa take Brufen with his medicines?" needs a check, and a language model asked the same question will sometimes answer from memory and sometimes say "it's safe".
**Decision.** A `health_records` MCP server resolves every product to molecules (`health/catalog.py`), then finds duplicate molecules and interactions by table lookup. Each interaction row carries a severity and a source. The model only renders what the tool returned. The verifier adds two criteria: `no_safety_verdict` ("is safe", "no interactions", "fine to take" are rejected unless quoted from data) and `interactions_from_database` (naming a medicine interaction without a health-tool citation is rejected). Unknown products stay unresolved — never guessed. A clear result is reported as "none recorded here", never "safe". Recent pharmacy orders count for the member's own check (Dolo last week + Combiflam today).
**Alternatives.** LLM-only interaction answers (unbounded, unauditable); a full DDI database such as DDInter/DrugBank (right for production; licensing and size are out of scope for the demo — the table interface stays the same).
**Consequences.** + Every flag is traceable to a row and a source; the eval set gates the wording. − The curated table is small: it is a demo set, labelled as such in the tool note and the KB. Production swaps in a licensed DDI source behind the same `interactions_between()` call.
